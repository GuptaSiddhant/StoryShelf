The client CLI talks to a running StoryShelf server over `/api/v1` and carries no Playwright or server dependencies. Run it with your package manager's runner:

<PackageManagers type="dlx" pkg="storyshelf" args="--help" />

> **Package reference:** For install and programmatic use see [@storyshelf/cli](/packages/cli/).

## `storyshelf init`

Initialize the current Storybook with `.storybook/storyshelf.json` (client config). Fails if `.storybook/main.*` is not found.

```bash
storyshelf init --url http://localhost:3000 --slug my-design-system --build-dir storybook-static
# or with prompts:
storyshelf init
# ? Server URL? http://localhost:3000 (detected React-Vite • 1 addons)
# ? Project slug? my-design-system
# also: --build-dir, --build-command, --build-script-name, --skip, -c/--config
```

Writes `.storybook/storyshelf.json: { "slug": "...", "url": "...", "buildDir": "...", "skip": "..." }` (no token, see [Configuration](/guides/config/)). Token stays in `SHELF_TOKEN` env / `--token`.

## `storyshelf create`

Create a project on the server (requires site-admin token) and write `.storybook/storyshelf.json`.

```bash
storyshelf create --url http://localhost:3000 --name "My Design System" --token $SHELF_ADMIN_TOKEN
# also reads SHELF_ADMIN_TOKEN env if --token omitted
```

Prints `Project slug: ...` and `CI token: ...`.

## `storyshelf build`

Build the Storybook output without uploading — same `buildDir`/`buildCommand` resolution as `upload`, but no server contact.

```bash
storyshelf build
storyshelf build --force-build
storyshelf build --build-dir dist-storybook --build-command "nx run app:build-storybook"
```

Prints `Build ready: <dir>` and fails fast when the output lacks `index.json`.

## `storyshelf upload`

Build (optionally), zip, and upload a Storybook build for capture.

```bash
# explicit flags
storyshelf upload \
  --url http://localhost:3000 \
  --slug my-design-system \
  --token shelf_xxx \
  --sha "$GITHUB_SHA" \
  --branch "$GITHUB_REF_NAME"

# with .storybook/storyshelf.json present (no args defaults to upload)
storyshelf
storyshelf upload --token shelf_xxx --sha $GITHUB_SHA --branch main
```

| Flag                              | Description                                                                                                                                                                           |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--url`                           | Server URL (or file / `SHELF_URL`)                                                                                                                                                    |
| `--slug`                          | Project slug (or file / `SHELF_SLUG`)                                                                                                                                                 |
| `--token`                         | Project API token (`Authorization: Bearer`, or `SHELF_TOKEN`)                                                                                                                         |
| `--sha`                           | Revision SHA (flag, CI env, local git HEAD, or synthesized `local-*`)                                                                                                                 |
| `--branch`                        | Baseline namespace (flag, CI env, local git branch, or `local`)                                                                                                                       |
| `--build-dir` / `-d`              | Built Storybook directory (default `storybook-static`)                                                                                                                                |
| `--config` / `-c`                 | Config file path (default `.storybook/storyshelf.json`)                                                                                                                               |
| `--build-command`                 | Custom build command (mutually exclusive with `--build-script-name`)                                                                                                                  |
| `--build-script-name` / `-b`      | npm script to build (default `build-storybook`)                                                                                                                                       |
| `--force-build`                   | Force rebuild even if `buildDir` exists                                                                                                                                               |
| `--skip`                          | Glob to skip upload (e.g. `"main"`)                                                                                                                                                   |
| `--message`                       | Build message                                                                                                                                                                         |
| `--author-name`, `--author-email` | Author attribution                                                                                                                                                                    |
| `--label key=value`               | Attach a build label (repeatable)                                                                                                                                                     |
| `--full`                          | Disable affected capture for this upload (render every story)                                                                                                                         |
| `--skip-unchanged`                | Record a commit that changed no story as a skipped build instead of uploading (default off; see [Skipping unchanged commits](/concepts/affected-capture/#skipping-unchanged-commits)) |
| `--untraced <glob>`               | Exclude matching files from affected tracing (repeatable, e.g. `"**/*.generated.ts"`; unions with `untraced` in config)                                                               |
| `--stats-file <path>`             | Bundler stats file (default `<buildDir>/preview-stats.json`)                                                                                                                          |
| `--zip`                           | Upload one zip instead of hashing files; for servers without the hash routes (or `SHELF_ZIP=1`)                                                                                       |
| `--json`                          | Print one JSON object on stdout when the command finishes (see [Machine-readable output](#machine-readable-output)); all human output goes to stderr                                  |
| `--wait`                          | After the upload, follow the build until it stops needing the server, and exit by how it ended (see [Gating CI with `--wait`](#gating-ci-with---wait))                                |
| `--timeout <duration>`            | With `--wait`, stop waiting after this long: `90`, `90s`, `30m`, `2h` (default `30m`). Never cancels the build                                                                        |
| `--dry-run`                       | Validate/build but send no requests                                                                                                                                                   |

Affected capture is on by default: the CLI traces `git diff baseline..HEAD` through the build's dependency graph, posts the affected set, and prints a summary (`Affected capture: rendering 3 stories (baseline abc1234)`). Anything it cannot prove unchanged renders anyway — see [Affected capture](/concepts/affected-capture/). `SHELF_FULL=1` and `"affectedOnly": false` opt out the same way as `--full`.

`--skip-unchanged` (or `"skipUnchanged": true`, or `SHELF_SKIP_UNCHANGED=1`) asks the server for the build to repeat before it creates one. When no story is affected, it prints `Skipped: no story changed since abc1234 (build 01J…)` and sends no Storybook. Every other case, errors included, prints one line saying why and uploads normally; skipping never fails an upload. `--full` always disables it.

:::note
The CLI does **not** run Playwright. It hashes the static build, sends only the files the server does not hold yet, then posts the manifest; the server renders and diffs asynchronously. A second upload of an unchanged build sends the manifest alone.
:::

### Machine-readable output

Scripts should not parse the text output, which can change between releases. `storyshelf upload --json` prints exactly one JSON object on stdout when the command finishes; phases, progress and every other message go to stderr, and the exit codes are unchanged.

```json
{
  "buildId": "01J…",
  "url": "https://shelf.example.com/projects/demo/builds/01J…",
  "status": "created",
  "skipped": false
}
```

| Field      | Meaning                                                                                                  |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| `buildId`  | The build's id; `null` when no build was made (`--dry-run`, or a branch skipped by the config's `skip`)  |
| `url`      | The build page, as the server returned it; `null` for a server that returns none                         |
| `status`   | `created`, `skipped` (a skipped build, or the config skips the branch) or `dry-run`                      |
| `skipped`  | `true` when no Storybook was uploaded because nothing needed it                                          |
| `verdict`  | With `--wait`: `approved`, `needs-review`, `rejected`, `failed`, `cancelled`, `timeout` or `interrupted` |
| `exitCode` | With `--wait`: the exit code the command ends with                                                       |

The output never contains a token. With `jq`, on any CI system:

```sh
url=$(npx storyshelf upload --json | jq -r .url)
```

On GitHub Actions, when `GITHUB_OUTPUT` is set, `upload` also appends `build-id` and `build-url` to that file (with or without `--json`), so a later step reads `steps.<id>.outputs.build-url`. GitLab CI has no equivalent step-output file; use `--json` with `jq`.

### Gating CI with `--wait`

`storyshelf upload --wait` follows the build after the upload: `==> Publishing`, then `==> Capturing 120/860 stories`, then the verdict, so a CI job can gate on visual changes without the git integration. The wait ends once the build stops needing the _server_. It never waits for a person: a build that needs a review ends the wait with exit code 2.

| Exit | The build ended as                                                                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0`  | Approved: no changes, an [unchanged-commit skip](/concepts/affected-capture/#skipping-unchanged-commits), or a hosting-only build accepted on publish                            |
| `2`  | Changes need review (`N visual changes need review`), or, on a [hosting-only](/concepts/hosting-only/) server with review on, the Storybook is published and waits for a verdict |
| `3`  | Rejected                                                                                                                                                                         |
| `4`  | Failed, including a failing Storybook test, which blocks                                                                                                                         |
| `5`  | Cancelled, including superseded by a newer build (the newer build is named)                                                                                                      |
| `6`  | `--timeout` reached with the build still running: `Timed out waiting: still capturing; nothing was cancelled`                                                                    |
| `1`  | The CLI itself failed: config, network, auth, or the upload (unchanged)                                                                                                          |

The timeout and Ctrl+C stop the _wait_ only; the build keeps running and nothing is cancelled. Ctrl+C exits `130`. `--wait` polls `GET /api/v1/projects/:slug/builds/:id` every 2 s, backing off to 10 s, and honours `Retry-After` on a `429` or `503`; it never approves anything and prints no token or signed URL. On a server without `testing` the wait ends after publishing.

```sh
storyshelf upload --wait --timeout 20m
case $? in 0) ;; 2) echo "visual changes need review" ;; *) exit 1 ;; esac
```

**Output.** Phases and progress go to stderr; the summary and build link go to stdout. A run whose changes need review ends like this (exit code 2):

```text
Summary
  Files:    32
  Size:     4.8 MiB
  Stories:  full capture (24 stories)
  Build:    01M7YHNVJD84B65FX880D4FW57
  Time:     0.1s
View the build: http://localhost:3000/projects/my-design-system/builds/01M7YHNVJD84B65FX880D4FW57/diff
==> Capturing
--> Captured (5.0s)
26 visual changes need review
Review: http://localhost:3000/projects/my-design-system/builds/01M7YHNVJD84B65FX880D4FW57/diff
```

A build with nothing to review prints `Build approved` and `View: <url>` instead, and exits `0`.

**Servers without `testing`.** An instance that [hosts Storybooks only](/concepts/hosting-only/) reports `testing: false` when the build is created. `storyshelf upload` then skips the affected-capture computation, uploads as usual, and ends with `Testing is off on this server: the Storybook is published, but no captures or visual checks will run.`

**Servers without the hash routes.** An older server answers `404` to `/dedup`. The CLI then prints `The server has no hash upload routes; uploading a zip instead` and sends the zip as before. `--zip` (or `SHELF_ZIP=1`) skips the hash path and always sends the zip.

**Large Storybooks on hosts without a job consumer.** With `--zip`, a zip over the server's `maxInlineUnzipSize` is normally published by a background job. A serverless host runs no consumer, so it answers `413` with a message pointing to the file-by-file route (`/dedup`, `/content`, `/manifest`). `storyshelf upload --zip` handles that by itself: it prints `Zip is over the server's inline publish limit; uploading file by file instead`, hashes the build directory, uploads only the files the server lacks, and posts the manifest, which completes publishing. A `413` for `maxUploadBytes` is not retried this way; raise the limit instead.

**Rejected inline ZIPs.** A `422` means the server rejected an invalid, unsafe, or over-limit archive. The build ends `failed` and takes no further upload (a PUT to it answers `409`). The CLI prints the server's reason; it does not retry file by file to bypass extraction limits. Fix the Storybook output or ask the server administrator to adjust `maxZipEntries` or `maxUnzippedBytes`. Run `storyshelf upload` again to create a new build.

## `storyshelf doctor` / `whoami`

```bash
storyshelf doctor
# ✓ Storybook setup found (/work/app/.storybook/main.ts)
# ✓ Config loaded (slug "my-design-system")
# ✓ Connection: http://localhost:3000 / my-design-system (token present)
# ✓ Server reachable, project "My Design System" readable
# ✓ Token may upload builds
# ✓ Build output ready: storybook-static (16 top-level entries)
# ✓ Affected capture ready (history and stats available; Storybook project /work/app, repository root /work/app)

storyshelf whoami
# Server: http://localhost:3000
# Project: My Design System (my-design-system)
```

## `storyshelf retry` / `purge`

```bash
storyshelf retry --url http://localhost:3000 --slug my-design-system --build-id <id> [--token $SHELF_TOKEN]
storyshelf purge --url http://localhost:3000 --token $SHELF_ADMIN_TOKEN
```

`retry` re-runs capture. `purge` runs retention GC. `cancel [--dry-run]` cancels older unfinished builds.

## `storyshelf protect`

Print, validate and (only with `--apply`) write the branch rule that makes StoryShelf gate merges. It talks to GitHub or GitLab directly with an admin token; it does not contact your StoryShelf server.

```bash
storyshelf protect --provider github --repo acme/widgets [--branch main] [--prefix storyshelf] [--gate testing|review] [--token $GITHUB_TOKEN] [--apply]
storyshelf protect --provider gitlab --repo group/project [--host https://gitlab.example.com] [--token $GITLAB_TOKEN] [--apply]
```

It always prints the required check names (`<prefix>/testing`, or `<prefix>/review` with `--gate review`) and the manual steps. With a token (`--token`, or `GITHUB_TOKEN` / `GITLAB_TOKEN`) it also compares them with the branch's rule (on GitHub, a ruleset when one applies to the branch, else classic branch protection; the output says which, so a dry run shows the mechanism `--apply` would use): the exit code is `1` when something is missing and nothing was written (dry run, the default). `--apply` adds only the missing part. See [Let StoryShelf set the rule](/guides/merge-gate/#let-storyshelf-set-the-rule) for what each host supports.
