:::caution
The container image and the Terraform modules ship from the next release (v0.12.0). Until then, build the image from the repository's [Dockerfile](https://github.com/GuptaSiddhant/StoryShelf/blob/main/apps/server-image/Dockerfile), and pin the module to `main`.
:::

The AWS module in `deploy/terraform/aws` deploys the full product, the app plus capture, on ECS Fargate. It deploys the published image and never builds one. It replaces `storyshelf server terraform-aws`; a migration guide with `moved` blocks for stacks generated by that command is planned in #889. The module's [README](https://github.com/GuptaSiddhant/StoryShelf/blob/main/deploy/terraform/aws/README.md) is the reference for names and defaults; this page explains the choices.

## Architecture

```txt
Internet ──▶ ALB (HTTPS, only allowed_cidr_blocks)
                │
                ▼
        ECS Fargate service: identical copies (app + capture, bundled Chromium)
          │            │              │
          │            │              └──▶ Secrets Manager (SECRET, AUTH_PASSWORD, ADMIN_TOKEN, …)
          │            └──▶ S3 bucket (private, versioned, encrypted)
          └──▶ RDS Postgres (private subnets, IAM authentication)

        Cognito user pool      CloudWatch Logs      Route 53 + ACM (with a domain)
```

- One Fargate service runs the UI, the API and capture. Every copy also consumes the database queue, so scaling means more identical copies.
- The network has two public and two private subnets and **no NAT gateway** (about 32 USD a month per zone). Tasks run in the public subnets with a public IP to pull the image and reach AWS APIs; their security group admits only the load balancer. The database is reachable from the task security group only.
- Secrets reach the task as ECS `secrets` references. No output carries a secret value.

## Use the module

Address the module by release tag through a git source, and give `image_version` the same version:

```hcl
module "storyshelf" {
  source = "git::https://github.com/GuptaSiddhant/StoryShelf.git//deploy/terraform/aws?ref=v0.12.0"

  name                = "storyshelf"
  region              = "us-east-1"
  image_version       = "0.12.0"
  domain_name         = "shelf.example.com"
  allowed_cidr_blocks = ["203.0.113.0/24"] # your office or VPN; ["0.0.0.0/0"] publishes the app
}
```

Or run `storyshelf server init --cloud aws`, which writes a `main.tf` that uses the module at the CLI's own version and a `terraform.tfvars` with your answers. Terraform is never applied for you: run `terraform init` and `terraform plan`, review it, then `terraform apply`. Each release also attaches `storyshelf-terraform-<version>.tar.gz` for installs that cannot fetch from GitHub. To upgrade, change both versions together and read the release notes.

### Inputs

| Name | Default | Meaning |
| --- | --- | --- |
| `name` | required | Name prefix, 2 to 20 characters |
| `image_version` | required | Release version of the image (no `v`) |
| `allowed_cidr_blocks` | required | IPv4 ranges that may reach the load balancer. `["0.0.0.0/0"]` publishes the app |
| `region` | `us-east-1` | Must match the provider's region |
| `image_repository` | `ghcr.io/guptasiddhant/storyshelf` | Registry path, for a mirror |
| `domain_name` | `""` | Enables HTTPS with a Route 53 zone and an ACM certificate |
| `allow_http` | `false` | Plain HTTP when there is no domain. Throwaway stacks only |
| `vpc_id` | `""` | An existing VPC. Subnets are found by their `Tier` tag (`public`, `private`) |
| `saml_metadata_url` | `""` | Cognito SAML federation |
| `task_cpu`, `task_memory` | `2048`, `4096` | Capture renders in the container, so do not go much lower |
| `min_instances`, `max_instances` | `1`, `1` | Identical copies, scaled on CPU. See [Running several instances](/guides/deployment/#running-several-instances) |
| `database_pool_size` | `10` | Connections per copy. `max_instances` × this must fit the database's limit |
| `existing_database_url_secret_arn` | `""` | A Postgres URL in Secrets Manager. No database is created |
| `database_instance_class`, `database_allocated_storage` | `db.t4g.micro`, `20` | Created database only (GiB) |
| `deletion_protection` | `true` | Database protection and a final snapshot. `false` also empties the bucket on destroy |
| `remote_browser_endpoint_secret_arn`, `remote_browser_token_secret_arn` | `""` | Optional [remote browser](/guides/remote-browsers/), as secret references |
| `shutdown_grace_seconds` | `30` | ALB and ECS drain timings (see the module README) |
| `log_retention_days`, `tags` | `30`, `{}` | CloudWatch retention and tags |

### Outputs

| Output | Meaning |
| --- | --- |
| `url`, `alb_dns_name` | The public base URL and the load balancer's DNS name |
| `s3_bucket` | The Storybook bucket |
| `db_endpoint`, `db_iam_user`, `db_master_secret_arn` | The database host, the IAM user and the master secret (a reference) |
| `user_pool_id`, `app_client_id` | Cognito |
| `cluster_name`, `service_name` | For `aws ecs update-service` |
| `admin_token_secret_arn`, `auth_password_secret_arn`, `oidc_client_secret_arn` | Secret references, never values |
| `task_role_arn`, `task_role_policy_json`, `execution_role_policy_json` | The exact permissions (next section) |

## Permissions

The task role is exactly the `task_role_policy_json` output, so a platform team can copy it into its own stack:

- `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` on the Storybook bucket's objects, and `s3:ListBucket` on the bucket;
- `rds-db:connect` on the database user `shelf` (not added when you pass your own database URL);
- `logs:CreateLogStream` and `logs:PutLogEvents` on the app's log group.

The separate execution role (ECS itself, before the app starts) has `AmazonECSTaskExecutionRolePolicy` plus `secretsmanager:GetSecretValue` on the app's secret ARNs only (`execution_role_policy_json`).

## Database and sign-in

- **IAM authentication.** The app connects through the `db-postgres/rds-iam` preset with a short-lived token from its task role, so there is no database password to read or rotate. Server certificates are verified against the Amazon RDS root certificates.
- **One operator step.** Once, from inside the VPC, connect with the master secret and run `GRANT rds_iam TO shelf;`. After that, `shelf` logs in only with an IAM token, including for your own administration. Run the grant last. The module README explains how to use a separate application user instead.
- **Sign-in.** The module always sets `AUTH_PASSWORD` and `SECRET`, so the app never starts open. Read the password with `aws secretsmanager get-secret-value --secret-id "$(terraform output -raw auth_password_secret_arn)"` and sign in as `admin@example.com`. The Cognito pool is created, but the image does not read OIDC settings yet, so Cognito sign-in is not wired.
- **State holds secrets.** `SECRET`, `AUTH_PASSWORD` and `ADMIN_TOKEN` are generated by Terraform and their values are in its state, so keep the state in an encrypted backend that few people can read.

## Domain and TLS

Without `domain_name` the plan fails unless `allow_http = true`. With a domain, ACM validates only once the domain's name servers point at the new Route 53 zone, so apply in two steps:

```sh
terraform apply -target='module.storyshelf.aws_route53_zone.main'
terraform state show 'module.storyshelf.aws_route53_zone.main[0]'   # copy the name_servers
# At your registrar (or the parent zone) create NS records for the domain with those servers.
terraform apply
```

## Sizing and cost

For a small team (a few projects, a few builds a day) the defaults are the starting point: one 2 vCPU and 4 GB Fargate task and a `db.t4g.micro` database with 20 GB. Rough monthly cost is **100 to 150 USD** (the always-on task, the load balancer and the database, plus storage and transfer). Treat that as an order of magnitude and check the AWS calculator for your region. Capture is the largest variable cost: Chromium needs about 100 to 300 MB per open page. See [Sizing memory for capture](/guides/deployment/#sizing-memory-for-capture).

## Backups

- **Database.** RDS automated snapshots, with a retention you choose, and a manual snapshot before upgrades. `deletion_protection` keeps a final snapshot on destroy.
- **Storage.** The bucket is versioned, so an overwritten or deleted blob can be recovered.
- **Order and restore.** Back up the database first, then storage, and restore both together. See [Back up and restore](/guides/backup-restore/), and run `storyshelf server check-storage` after a restore.

## Adapt it to your own platform

If your team won't use the module, you need three things:

1. **The image.** `ghcr.io/guptasiddhant/storyshelf:<version>` (`amd64` and `arm64`). It listens on port 3000 and bundles Chromium. Use at least 2 vCPU and 4 GB for capture; the `-hosting` variant has no browser.
2. **The environment.** This is what the module passes:

   | Variable | Value |
   | --- | --- |
   | `AWS_BUCKET`, `AWS_REGION` | The bucket and its region. Credentials come from the task role |
   | `PUBLIC_BASE_URL`, `TRUST_PROXY` | The public `https://` origin, and `1` behind a load balancer |
   | `SECRET` | At least 32 random characters, the same on every copy (a secret reference) |
   | `AUTH_PASSWORD`, `ADMIN_TOKEN` | Admin sign-in and API token (secret references) |
   | `DATABASE_URL` | A Postgres URL with `?sslmode=require`, **or** the four `DATABASE_IAM_HOST`, `_USER`, `_NAME`, `_REGION` for IAM authentication |
   | `DATABASE_POOL_MAX` | Connections per copy |

3. **The permissions** in the section above, attached to the task's own role. Never put access keys in environment files.

Put a load balancer in front that terminates TLS, and keep the database off the public internet.
