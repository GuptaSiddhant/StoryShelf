title: AWS deployment

For AWS-only enterprise deployments, `storyshelf server init` offers an `aws` deploy target that pins the full reference stack — one ECS Fargate app service (it serves the UI and runs the captures from the database queue), S3, Postgres (RDS), Cognito, Secrets Manager, CloudWatch, and an optional Route 53 + ACM front door — and writes it as Terraform under `terraform/`.

## Scaffold

```bash
storyshelf server init
# ? Deploy target? AWS (ECS + S3 + Postgres + Cognito)
# ? AWS region? us-east-1
# ? Public domain for the ALB? (empty leaves it HTTP-only)
# ? SAML metadata URL for Cognito federation? (empty skips it)
```

## Apply

Terraform is never auto-applied — review explicitly:

```bash
cd my-server
terraform -chdir=terraform init
terraform -chdir=terraform plan -out=tfplan   # review before applying
terraform -chdir=terraform apply tfplan       # or: npm run infra:apply
```

## Networking

With no existing VPC (the default), the scaffold creates the network: a VPC with 2 public and 2 private subnets across 2 availability zones (tagged `Tier = public` / `Tier = private`), an internet gateway and a public route table.

- **No NAT gateway.** It costs about $32/month per availability zone, so the scaffold leaves it out. The ALB and the ECS tasks run in the public subnets and the tasks get a public IP, which is how they pull the image and reach S3, Secrets Manager and CloudWatch. Their security group admits traffic only from the ALB.
- **Private database.** RDS sits in the private subnets, which need no internet egress.
- **Existing VPC.** Supply `vpc_id` and the scaffold looks subnets up by their `Tier` tag instead of creating any. Tag at least two public subnets in different availability zones `Tier = public` (the ALB and the tasks) and at least two subnets in different availability zones `Tier = private` (an RDS subnet group needs two); the public subnets need a route to an internet gateway.

The IAM roles are least-privilege: the task execution role pulls the image, writes logs and reads the three app secrets plus the RDS-managed database secret; the task role reads exactly the three app secrets and reads and writes only the Storybook bucket.

## Database and secrets

- **Database access.** Postgres sits behind its own security group that admits port 5432 only from the ECS task security group.
- **Database credentials.** RDS creates and manages the master password itself, in its own Secrets Manager secret, so it is never in Terraform state. The task reads the username and password from that secret and builds `DATABASE_URL` (password percent-encoded, `?sslmode=require`) when it starts.
- **`SECRET` and `ADMIN_TOKEN`** are generated by Terraform (`random_password`) and stored in Secrets Manager. Their values are also in the Terraform state, so keep the state in an encrypted backend with restricted access.
- **`OIDC_CLIENT_SECRET` is an operator step.** Terraform writes the placeholder `change-me` once, so the first task can start, and never overwrites it. Put the real client secret in, then restart the service so the task picks it up:

```bash
aws secretsmanager put-secret-value --secret-id "<project>/OIDC_CLIENT_SECRET" --secret-string "<client secret>"
aws ecs update-service --cluster <project>-cluster --service <project>-app --force-new-deployment
```

The task also receives `PUBLIC_BASE_URL`: `https://<domain>` when a domain is set, otherwise `http://<ALB DNS name>`.

## Domain and TLS

Without a domain the ALB serves plain HTTP only. With one, Terraform creates a Route 53 zone for it, an ACM certificate validated through DNS records in that zone, an HTTPS listener that uses the validated certificate, and a 301 redirect from port 80 to HTTPS.

**Operator step: delegate the domain to the new zone.** ACM can only validate the certificate once the domain's name servers point at the zone Terraform created, so apply in two steps:

```bash
terraform -chdir=terraform apply -target='aws_route53_zone.main'
terraform -chdir=terraform state show 'aws_route53_zone.main[0]'   # copy the name_servers
# At your registrar (or the parent zone), create NS records for the domain with those servers.
terraform -chdir=terraform apply                                   # now the certificate validates
```

## Wiring outputs

Wire the outputs into env (`terraform output -json` / `npm run infra:outputs`): `S3_BUCKET` + `AWS_REGION`, `DATABASE_URL` (`?sslmode=require`), `COGNITO_REGION` / `COGNITO_USER_POOL_ID` / `OIDC_*`, `SECRET`. Output keys (`alb_dns_name`, `s3_bucket`, `db_endpoint`, `user_pool_id`, `app_client_id`) are a stable contract parsed by CI — they never change.

Credentials come from IAM task roles — never check access keys into env files. Corporate SSO federates through Cognito SAML (Entra/Okta via `samlMetadataUrl`); `adminGroups: ["shelf-admins"]` maps the Cognito group to site admin.

Pair with [@storyshelf/storage-s3](/packages/storage-s3/) and [@storyshelf/db-postgres](/packages/db-postgres/) — the scaffold already wires them. The database is also the capture queue, so there is no queue or worker to provision; to capture more builds at once, raise the service's task count.
