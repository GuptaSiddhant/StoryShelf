:::caution
The container image and the Terraform modules ship from the next release (v0.12.0). Until then, build the image from the repository's [Dockerfile](https://github.com/GuptaSiddhant/StoryShelf/blob/main/apps/server-image/Dockerfile), and pin the module to `main`.
:::

The AWS module in `deploy/terraform/aws` deploys the full product, the app plus capture, on ECS Fargate. It deploys the published image and never builds one. It replaces `storyshelf server terraform-aws`; the [migration guide](/guides/deployment/migrate-terraform/) maps stacks generated by that command to the module. The module's [README](https://github.com/GuptaSiddhant/StoryShelf/blob/main/deploy/terraform/aws/README.md) is the reference for names and defaults; this page explains the choices.

## Architecture

```txt
Internet ──▶ ALB (HTTPS, only allowed_cidr_blocks)
                │
                ▼
        ECS Fargate service: identical copies (app + capture, bundled Chromium)
          │            │              │
          │            │              └──▶ Secrets Manager (SHELF_SECRET, SHELF_ADMIN_PASSWORD, SHELF_ADMIN_TOKEN, …)
          │            └──▶ S3 bucket (private, versioned, encrypted)
          └──▶ RDS Postgres (private subnets, IAM authentication)

        CloudWatch Logs      Route 53 + ACM (with a domain)      Cognito (optional)
```

- One Fargate service runs the UI, the API and capture. Every copy also consumes the database queue, so scaling means more identical copies.
- The network has two public and two private subnets and **no NAT gateway** (about 32 USD a month per zone). Tasks run in the public subnets with a public IP to pull the image and reach AWS APIs; their security group admits only the load balancer. The database is reachable from the task security group only.
- Secrets reach the task as ECS `secrets` references. No output carries a secret value.

## Use the module

Address the module by release tag through a git source, and give `image_version` the same version:

```hcl
module "storyshelf" {
  source = "git::https://github.com/GuptaSiddhant/StoryShelf.git//deploy/terraform/aws?ref=v0.12.0"

  name                = "storyshelf"
  region              = "us-east-1"
  image_version       = "0.12.0"
  domain_name         = "shelf.example.com"
  allowed_cidr_blocks = ["203.0.113.0/24"] # your office or VPN; ["0.0.0.0/0"] publishes the app
}
```

Or run `storyshelf server init --cloud aws`, which writes a `main.tf` that uses the module at the CLI's own version a `terraform.tfvars` with your answers, and a `.gitignore` for the state and plan, which hold the generated secrets (keep the state in an encrypted remote backend). Terraform is never applied for you: run `terraform init` and `terraform plan`, review it, then `terraform apply`. Each release also attaches `storyshelf-terraform-<version>.tar.gz` for installs that cannot fetch from GitHub. To upgrade, change both versions together and read the release notes.

### Inputs

| Name                                                    | Default                                           | Meaning                                                                                                                       |
| ------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `name`                                                  | required                                          | Name prefix, 2 to 20 characters                                                                                               |
| `image_version`                                         | required                                          | Release version of the image (no `v`)                                                                                         |
| `allowed_cidr_blocks`                                   | required                                          | IPv4 ranges that may reach the load balancer. `["0.0.0.0/0"]` publishes the app                                               |
| `region`                                                | `us-east-1`                                       | Must match the provider's region                                                                                              |
| `image_repository`                                      | `ghcr.io/guptasiddhant/storyshelf`                | Registry path, for a mirror                                                                                                   |
| `domain_name`                                           | `""`                                              | Enables HTTPS with a Route 53 zone and an ACM certificate                                                                     |
| `allow_http`                                            | `false`                                           | Plain HTTP when there is no domain. Throwaway stacks only                                                                     |
| `vpc_id`                                                | `""`                                              | An existing VPC. Subnets are found by their `Tier` tag (`public`, `private`)                                                  |
| `enable_cognito`, `saml_metadata_url`                   | `false`, `""`                                     | Create the Cognito pool and client (the image does not read OIDC settings yet), and its SAML federation                       |
| `auth_email`                                            | `admin@example.com`                               | The local admin's sign-in email                                                                                               |
| `task_cpu`, `task_memory`                               | `2048`, `4096`                                    | Capture renders in the container, so do not go much lower                                                                     |
| `min_instances`, `max_instances`                        | `1`, `1`                                          | Identical copies, scaled on CPU. See [Running several instances](/guides/deployment/#running-several-instances)               |
| `database_pool_size`                                    | `10`                                              | Connections per copy. `max_instances` × this must fit the database's limit                                                    |
| `existing_database_url_secret_arn`                      | `""`                                              | A Postgres URL in Secrets Manager. No database is created                                                                     |
| `database_instance_class`, `database_allocated_storage` | `db.t4g.micro`, `20`                              | Created database only (GiB)                                                                                                   |
| `database_backup_retention_days`                        | `7`                                               | Automated backup retention, 1 to 35 days                                                                                      |
| `database_init_image`                                   | ECR Public `postgres:16-alpine`, pinned by digest | Image of the first-boot `db-init` container (needs `psql`). It receives the master credentials, so pin a mirror by digest too |
| `deletion_protection`                                   | `true`                                            | Database protection and a final snapshot. `false` also empties the bucket on destroy                                          |
| `shutdown_grace_seconds`                                | `30`                                              | Sets `SHELF_SHUTDOWN_GRACE_SECONDS`, the ALB deregistration delay and the ECS stop timeout (see [Shutdown](#shutdown))        |
| `log_retention_days`, `tags`                            | `30`, `{}`                                        | CloudWatch retention and tags                                                                                                 |

## Permissions

The task role is exactly the `task_role_policy_json` output, so a platform team can copy it into its own stack:

- `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` on the Storybook bucket's objects, and `s3:ListBucket` on the bucket;
- `rds-db:connect` on the database user `shelf` (not added when you pass your own database URL).

The separate execution role (ECS itself, before the app starts) has `AmazonECSTaskExecutionRolePolicy` plus `secretsmanager:GetSecretValue` on the app's secret ARNs only (`execution_role_policy_json`). The `awslogs` driver writes the container's logs with the execution role, so the task role has no logs permission.

## Database and sign-in

- **IAM authentication.** The app connects through the `@storyshelf/db/postgres/rds-iam` preset with a short-lived token from its task role, so there is no database password for the app to read or rotate. The server certificate is **always verified**, against the Amazon RDS root certificates the image bundles (set `SHELF_DATABASE_CA` or `SHELF_DATABASE_CA_FILE` for an RDS Proxy or a custom domain). There is no setting that encrypts without verifying. See [Verify the database certificate](/guides/deployment/cloud/#verify-the-database-certificate).
- **No first-boot operator step.** RDS cannot grant `rds_iam`, so each task first runs a `db-init` container. It logs in as the master user with the RDS-managed secret, then idempotently creates the app user `shelf`, grants it `rds_iam` and gives it rights on the database. The app container starts only after `db-init` succeeds; its output is in the log group under the `db-init` stream prefix. Only `shelf` is IAM-only: the master user keeps its password in `db_master_secret_arn` for administration from inside the VPC.
- **Unverified.** The `db-init` step is checked by `terraform validate` only and has not yet run against a real RDS (tracked in #1096). The nightly `module-apply` live run is off until the owner enables it.
- **Sign-in.** The module always sets `SHELF_ADMIN_PASSWORD` and `SHELF_SECRET`, so the app never starts open. Read the password with `aws secretsmanager get-secret-value --secret-id "$(terraform output -raw auth_password_secret_arn)"` and sign in as `admin@example.com` (or `auth_email`). Cognito is off by default (`enable_cognito = false`) because the image does not read OIDC settings yet; with it on, `SHELF_OIDC_CLIENT_SECRET` is an operator step (Terraform writes `change-me` once, never overwrites it).
- **State holds secrets.** `SHELF_SECRET`, `SHELF_ADMIN_PASSWORD` and `SHELF_ADMIN_TOKEN` are generated by Terraform and their values are in its state, so keep the state in an encrypted backend that few people can read.

## Domain and TLS

Without `domain_name` the plan fails unless `allow_http = true`. The HTTPS listener allows TLS 1.2 and 1.3 only (`ELBSecurityPolicy-TLS13-1-2-2021-06`), and the load balancer drops invalid header fields. With a domain, ACM validates only once the domain's name servers point at the new Route 53 zone, so apply in two steps:

```sh
terraform apply -target='module.storyshelf.aws_route53_zone.main'
terraform state show 'module.storyshelf.aws_route53_zone.main[0]'   # copy the name_servers
# At your registrar (or the parent zone) create NS records for the domain with those servers.
terraform apply
```

## Keep one instance running and shutdown

Capture and publishing run in the background, so the service keeps `min_instances` at 1 or more (the default). Do not scale it to zero: see [Keep one instance running](/guides/deployment/#keep-one-instance-running). Fargate has no CPU throttling to turn off.

### Shutdown

On a deploy ECS sends SIGTERM, and the app drains running captures for `SHELF_SHUTDOWN_GRACE_SECONDS`, then hands the rest back to the queue. The module sets the variable from `shutdown_grace_seconds` (30), the ALB deregistration delay to the same value, and the ECS `stopTimeout` to the grace plus 10 seconds (Fargate allows at most 120), so the container is not killed mid-drain.

## Sizing and cost

For a small team (a few projects, a few builds a day) the defaults are the starting point: one 2 vCPU and 4 GB Fargate task and a `db.t4g.micro` database with 20 GB. Rough monthly cost is **100 to 150 USD** (an estimate, November 2026, for `us-east-1`) (the always-on task, the load balancer and the database, plus storage and transfer). Treat that as an order of magnitude and check the AWS calculator for your region. Capture is the largest variable cost: Chromium needs about 100 to 300 MB per open page. See [Sizing memory for capture](/guides/deployment/#sizing-memory-for-capture).

## Backups

- **Database.** RDS automated backups and point-in-time recovery (`database_backup_retention_days`, 7 by default, up to 35), and a manual snapshot before upgrades. `deletion_protection` keeps a final snapshot on destroy.
- **Storage.** The bucket is versioned, so an overwritten or deleted blob can be recovered.
- **Order and restore.** Back up the database first, then storage, and restore both together. See [Back up and restore](/guides/backup-restore/), and run `storyshelf-server check-storage` after a restore.

## Adapt it to your own platform

If your team won't use the module, you need three things:

1. **The image.** `ghcr.io/guptasiddhant/storyshelf:<version>` (`amd64` and `arm64`). It listens on port 3000 and bundles Chromium. Use at least 2 vCPU and 4 GB for capture; the `-hosting` variant has no browser.
2. **The environment.** This is what the module passes:

   | Variable                                     | Value                                                                                                                                                                                          |
   | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `SHELF_S3_BUCKET`, `AWS_REGION`              | The bucket and its region. Credentials come from the task role                                                                                                                                 |
   | `SHELF_PUBLIC_BASE_URL`, `SHELF_TRUST_PROXY` | The public `https://` origin, and `1` behind a load balancer                                                                                                                                   |
   | `SHELF_SECRET`                               | At least 32 random characters, the same on every copy (a secret reference)                                                                                                                     |
   | `SHELF_ADMIN_PASSWORD`, `SHELF_ADMIN_TOKEN`  | Admin sign-in and API token (secret references)                                                                                                                                                |
   | `DATABASE_URL`                               | A Postgres URL (`?sslmode=verify-full` with `SHELF_DATABASE_CA_FILE` to verify the certificate), **or** the four `SHELF_DATABASE_IAM_HOST`, `_USER`, `_NAME`, `_REGION` for IAM authentication |
   | `SHELF_DATABASE_POOL_MAX`                    | Connections per copy                                                                                                                                                                           |
   | `SHELF_SHUTDOWN_GRACE_SECONDS`               | Drain time on SIGTERM. Keep it below your platform's stop timeout                                                                                                                              |

3. **The permissions** in the section above, attached to the task's own role. Never put access keys in environment files.

Put a load balancer in front that terminates TLS, and keep the database off the public internet.
