:::note
The input and output tables below follow [ADR 0050](https://github.com/GuptaSiddhant/StoryShelf/blob/main/docs/adr/0050-cloud-deployment.md) and are checked against the module when it lands. The module's own `README.md` is the final word on names and defaults.
:::

The Azure module in `deploy/terraform/azure` deploys the full product, the app plus capture, on Azure Container Apps. It deploys the published image and never builds one. It replaces `storyshelf server terraform-azure`; if you have a stack generated by that command, a migration guide with `moved` blocks maps its resources to the module (planned in #889).

## Architecture

```txt
Internet ──▶ Container Apps environment (ingress, HTTPS)
                  │
                  └──▶ Container App (app + capture, min 1 replica)
                          │       │        │
                          │       │        └──▶ Blob storage (Storybooks, screenshots)
                          │       └──▶ Key Vault
                          └──▶ PostgreSQL Flexible Server (private access)
                              Log Analytics
```

- One container service runs the UI, the API and capture (the image bundles Chromium). Every copy also consumes the database queue, so scaling means more identical copies.
- Azure Database for PostgreSQL, Flexible Server is reachable only on private networking.
- Secrets come from Key Vault as references, never as plain outputs.

## Use the module

Address the module by release tag through a git source, so an upgrade is a change of `ref`:

```hcl
module "storyshelf" {
  source = "git::https://github.com/GuptaSiddhant/StoryShelf.git//deploy/terraform/azure?ref=v0.12.0"

  image_version = "0.12.0"
  location      = "eastus"
}
```

Or let the CLI write this for you: `storyshelf server init --cloud azure` writes a `main.tf` that uses the module at the CLI's own version and a `terraform.tfvars` with your answers. Terraform is never applied for you: run `terraform init`, `terraform plan` and review it before `terraform apply`.

### Inputs

| Input | Purpose |
| --- | --- |
| `image_version` | The published image tag to deploy (`ghcr.io/guptasiddhant/storyshelf`). Required. |
| `region` | The Azure region (`location`). |
| `domain` | Optional public domain. Empty leaves the default `azurecontainerapps.io` URL. |
| `min_instances`, `max_instances` | Copies of the container. See [Running several instances](/guides/deployment/#running-several-instances) for per-copy limits. |
| `db_pool_size` | Database connections per copy. Keep `max_instances` × this under the database's connection limit. |
| `database_url` | An existing Postgres URL (reference to a secret). Leave empty and the module creates Azure Database for PostgreSQL, Flexible Server. |
| `playwright_workspace` | Optional. Attach an Azure Playwright Workspace through the `azurePlaywright` preset. The preset is experimental; the nightly Azure run verifies it. |

### Outputs

| Output | Meaning |
| --- | --- |
| `app_fqdn` | The app's hostname. |
| `storage_connection_string` | A reference to the secret holding the connection string, not the string. |
| `database_url` | A reference to the secret holding the database URL. |
| `iam_policy` | The exact permissions the app gets (next section). |

## Permissions

The app gets only what it uses:

- **Managed identity of the app:** `Key Vault Secrets User` on the app's vault, and `Storage Blob Data Contributor` on the Storybook container only.
- **Image pull:** none needed for the public image; a private mirror needs `AcrPull` on that registry.

Review these with your platform team before the first apply. They are also what you copy if you [adapt it to your own platform](#adapt-it-to-your-own-platform).

## Sizing and cost

A small team (a few projects, a few hundred captures per build, a handful of builds a day):

| Part | Starting point |
| --- | --- |
| Container | 1 vCPU and 2 GiB, `min_replicas = 1` (2 vCPU and 4 GiB for parallel captures) |
| Instances | `min_instances = 1`, `max_instances = 2` |
| Database | `B_Standard_B1ms` burstable, 32 GB |

Rough monthly cost: about 70 to 120 USD for one always-on replica and a burstable Postgres server, plus storage and egress. Prices change by region and over time; treat this as an order of magnitude and check your cloud's calculator. Capture is the largest variable cost, since Chromium needs about 100 to 300 MB per open page. See [Sizing memory for capture](/guides/deployment/#sizing-memory-for-capture).

## Backups

- **Database.** Flexible Server keeps automated backups; set the retention (up to 35 days) and use geo-redundant backup if you need it.
- **Storage.** Turn on bucket versioning (blob versioning and soft delete on the storage account), so an overwritten or deleted blob can be recovered.
- **Order and restore.** Back up the database first, then storage, and restore both together. See [Back up and restore](/guides/backup-restore/), and run `storyshelf server check-storage` after a restore.

## Adapt it to your own platform

If your team won't use the module, you need three things:

1. **The image.** `ghcr.io/guptasiddhant/storyshelf:<version>` (`amd64` and `arm64`). It listens on port 3000 and bundles Chromium. A `-hosting` variant has no browser, for hosting without capture. Any container service that runs it with at least 1 vCPU and 2 GB works.
2. **The environment.**

   | Variable | Value |
   | --- | --- |
   | `SECRET` | At least 32 random characters, the same on every copy. |
   | `DATABASE_URL` | A Postgres URL (the server's private hostname, `?sslmode=require`). |
   | `AZURE_STORAGE_CONNECTION` | The storage connection, read from Key Vault. |
      | `PUBLIC_BASE_URL` | The public `https://` origin, so notifications and links are built. |
   | `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | Optional sign-in. See [Auth](/guides/auth/). |

3. **The permissions** in the section above, attached to the container's own identity. Never put cloud access keys in environment files.

Put a load balancer or ingress in front that terminates TLS and forwards the original host. Keep the database off the public internet.
