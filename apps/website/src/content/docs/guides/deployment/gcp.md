:::caution
The container image and the Terraform modules ship from the next release (v0.12.0). Until then, build the image from the repository's [Dockerfile](https://github.com/GuptaSiddhant/StoryShelf/blob/main/apps/server-image/Dockerfile), and pin the module to `main`.
:::

:::note
The input and output tables below follow [ADR 0050](https://github.com/GuptaSiddhant/StoryShelf/blob/main/docs/adr/0050-cloud-deployment.md) and are checked against the module when it lands. The module's own `README.md` is the final word on names and defaults.
:::

The GCP module in `deploy/terraform/gcp` deploys the full product, the app plus capture, on Cloud Run (CPU always allocated, so capture keeps running). It deploys the published image and never builds one. It replaces `storyshelf server terraform-gcp`; if you have a stack generated by that command, a migration guide with `moved` blocks maps its resources to the module (planned in #889).

## Architecture

```txt
Internet ──▶ Cloud Run service (app + capture)
                  │       │        │
                  │       │        └──▶ GCS bucket (Storybooks, screenshots)
                  │       └──▶ Secret Manager
                  └──▶ Cloud SQL Postgres (private IP, VPC connector)
                      Cloud Logging
```

- One container service runs the UI, the API and capture (the image bundles Chromium). Every copy also consumes the database queue, so scaling means more identical copies.
- Cloud SQL for PostgreSQL is reachable only on private networking.
- Secrets come from Secret Manager as references, never as plain outputs.

## Use the module

Address the module by release tag through a git source, so an upgrade is a change of `ref`:

```hcl
module "storyshelf" {
  source = "git::https://github.com/GuptaSiddhant/StoryShelf.git//deploy/terraform/gcp?ref=v0.12.0"

  image_version = "0.12.0"
  project_id    = "my-gcp-project"
  region        = "us-central1"
}
```

Or let the CLI write this for you: `storyshelf server init --cloud gcp` writes a `main.tf` that uses the module at the CLI's own version and a `terraform.tfvars` with your answers. Terraform is never applied for you: run `terraform init`, `terraform plan` and review it before `terraform apply`.

### Inputs

| Input | Purpose |
| --- | --- |
| `image_version` | The published image tag to deploy (`ghcr.io/guptasiddhant/storyshelf`). Required. |
| `region` | The GCP region. |
| `domain` | Optional public domain. Empty leaves the default `run.app` URL. |
| `min_instances`, `max_instances` | Copies of the container. See [Running several instances](/guides/deployment/#running-several-instances) for per-copy limits. |
| `db_pool_size` | Database connections per copy. Keep `max_instances` × this under the database's connection limit. |
| `database_url` | An existing Postgres URL (reference to a secret). Leave empty and the module creates Cloud SQL for PostgreSQL. |
| `project_id` | The GCP project to deploy into. |

### Outputs

| Output | Meaning |
| --- | --- |
| `run_url` | The Cloud Run service URL. |
| `gcs_bucket` | The Storybook bucket. |
| `database_url` | A reference to the secret holding the database URL, not the URL. |
| `iam_policy` | The exact permissions the app gets (next section). |

## Permissions

The app gets only what it uses:

- **Runtime service account:** `roles/cloudsql.client`, `roles/secretmanager.secretAccessor` on the app's secrets only, and `roles/storage.objectAdmin` on the Storybook bucket only.
- **No project-wide roles.** The module's `iam_policy` output lists the exact bindings.

Review these with your platform team before the first apply. They are also what you copy if you [adapt it to your own platform](#adapt-it-to-your-own-platform).

## Sizing and cost

A small team (a few projects, a few hundred captures per build, a handful of builds a day):

| Part | Starting point |
| --- | --- |
| Container | 1 vCPU and 2 GiB, CPU always allocated (2 vCPU and 4 GiB for parallel captures) |
| Instances | `min_instances = 1`, `max_instances = 2` |
| Database | `db-custom-1-3840` (a shared-core `db-f1-micro` is only for trials), 10 GB SSD |

Rough monthly cost: about 80 to 130 USD for one always-on Cloud Run instance and a small Cloud SQL instance, plus storage and egress. Prices change by region and over time; treat this as an order of magnitude and check your cloud's calculator. Capture is the largest variable cost, since Chromium needs about 100 to 300 MB per open page. See [Sizing memory for capture](/guides/deployment/#sizing-memory-for-capture).

## Backups

- **Database.** Turn on Cloud SQL automated backups and point-in-time recovery.
- **Storage.** Turn on bucket versioning (`versioning { enabled = true }` on the bucket), so an overwritten or deleted blob can be recovered.
- **Order and restore.** Back up the database first, then storage, and restore both together. See [Back up and restore](/guides/backup-restore/), and run `storyshelf server check-storage` after a restore.

## Adapt it to your own platform

If your team won't use the module, you need three things:

1. **The image.** `ghcr.io/guptasiddhant/storyshelf:<version>` (`amd64` and `arm64`). It listens on port 3000 and bundles Chromium. A `-hosting` variant has no browser, for hosting without capture. Any container service that runs it with at least 1 vCPU and 2 GB works.
2. **The environment.**

   | Variable | Value |
   | --- | --- |
   | `SECRET` | At least 32 random characters, the same on every copy. |
   | `DATABASE_URL` | A Postgres URL (the Cloud SQL private IP, `?sslmode=require`). |
   | `GCS_BUCKET`, `GOOGLE_CLOUD_PROJECT` | The bucket and project. Credentials come from the service account. |
      | `PUBLIC_BASE_URL` | The public `https://` origin, so notifications and links are built. |
   | `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | Optional sign-in. See [Auth](/guides/auth/). |

3. **The permissions** in the section above, attached to the container's own identity. Never put cloud access keys in environment files.

Put a load balancer or ingress in front that terminates TLS and forwards the original host. Keep the database off the public internet.
