StoryShelf is a self-hosted visual testing platform for Storybook. You run one server, point your CI at it, and review pixel diffs in the browser.

<Screenshot
  name="projects-list"
  alt="The projects overview: a card per project with its latest build and review backlog"
  caption="What you will end up with: a project per Storybook, and what still needs review."
/>

You need a Storybook with a `.storybook/main.*` file, and a machine to run the server on. Pick one way to start the server below (both end in the same place), then follow steps 2 to 4.

<Aside type="caution" title="Three values you must set">
  The server starts with sign-in on and refuses to start without these. There is no default for any of them.

  - `SECRET`: at least 32 random characters. Generate it once and keep it; the data volume needs the same value on every start.
  - `PUBLIC_BASE_URL`: the address people open in a browser, for example `http://localhost:3000`.
  - `AUTH_PASSWORD`: the first admin's password, at least 12 characters.
</Aside>

## 1. Start the server

<Tabs syncKey="server">
  <TabItem label="Docker">
    One command, with Chromium for capture, SQLite and local storage on a volume. Needs Docker.

    ```sh
    export SECRET="$(openssl rand -hex 32)"
    export PUBLIC_BASE_URL=http://localhost:3000
    # Choose a private admin password (12 or more characters); it is not echoed.
    printf 'Admin password: '; stty -echo; read -r AUTH_PASSWORD; stty echo; echo
    export AUTH_PASSWORD
    docker run -p 127.0.0.1:3000:3000 -v storyshelf:/data \
      -e SECRET -e PUBLIC_BASE_URL -e AUTH_PASSWORD \
      ghcr.io/guptasiddhant/storyshelf
    ```

    The server listens on `http://localhost:3000`. Keep `SECRET` somewhere safe: starting again on the same `storyshelf` volume needs the same value.
  </TabItem>
  <TabItem label="npm">
    Scaffold a server project and run it with Node.js 24 or later:

    <PackageManagers type="dlx" pkg="storyshelf" args="server init" />

    Accept the defaults (SQLite, local filesystem, **Local accounts**). It writes `src/index.ts`, a `package.json`, a `.env.example` and a short README, then prints the next steps:

    ```sh
    cd my-storyshelf
    export SECRET="$(openssl rand -hex 32)"
    export PUBLIC_BASE_URL=http://localhost:3000
    # Choose a private admin password (12 or more characters); it is not echoed.
    printf 'Admin password: '; stty -echo; read -r AUTH_PASSWORD; stty echo; echo
    export AUTH_PASSWORD
    npm install
    npm start
    ```

    The server listens on `http://localhost:3000`. Instead of exporting the variables, you can copy `.env.example` to `.env` and fill it in; the server reads `.env` when it starts. A missing value stops the server with one line naming it.

    Run `storyshelf server init` in a terminal: it asks questions and fails with a message, writing nothing, when it has no terminal. `--dir <path>` picks the output directory.
  </TabItem>
</Tabs>

## 2. Sign in and create a project

Open `http://localhost:3000` and sign in as `admin@example.com` with your `AUTH_PASSWORD`. Choose **New project**, give it a name, and open it. A project with no builds shows **Get your first build**:

1. **Create a token.** It is shown once; copy it.
2. **Upload.** The card shows the command with your server URL and the project's slug filled in.

## 3. Upload a build

From your Storybook project, run the command from the card:

<PackageManagers
  type="dlx"
  pkg="storyshelf"
  args="upload --url http://localhost:3000 --slug my-design-system"
/>

Set the token first: `STORYSHELF_TOKEN=shelf_… npx storyshelf upload …` (the card prints it that way). `upload` builds your Storybook first when there is no `storybook-static` directory, then uploads it. StoryShelf renders every story on the server and diffs it against the branch baseline; the card moves on when the first build arrives.

<Aside type="tip">
  To save the URL and slug so later runs need no flags, run `npx storyshelf init --url http://localhost:3000 --slug my-design-system`. It writes `.storybook/storyshelf.json`; keep the token in `STORYSHELF_TOKEN` (in CI, as a secret), never in the file. With the config in place, `npx storyshelf` alone uploads. For a complete pipeline, see [CI setup](/guides/ci/).

  On a server with sign-in off (`SHELF_AUTH=none` on the image, or a scaffold without auth), `npx storyshelf create --url http://localhost:3000 --name "My Design System"` creates the project and a CI token and writes the config in one step. With sign-in on it creates the project only, then points you to the project's page for the token: a token made from the command line has no user behind it, so it could not upload.
</Aside>

## 4. Review

The first build has nothing to compare against, so it waits for review: open the build and approve it to make it the baseline. Upload again and the new build is compared with that baseline; an unchanged Storybook passes with nothing to review. A build that needs attention shows **N to review** on its project card; open it, and choose **Review diffs** for the review workspace: a filmstrip of changed stories, baseline, current and diff side by side (or swiped, blended or flipped), and **Approve** / **Reject** with the keyboard.

<Screenshot
  name="diff-review"

  caption="The review workspace. Approving a change moves you straight to the next one."
/>

When every change is decided, the build's status check goes green and you can merge.
