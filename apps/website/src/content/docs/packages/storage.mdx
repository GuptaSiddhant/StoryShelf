`@storyshelf/storage` holds every storage backend StoryShelf ships outside core, one subpath each: `/s3`, `/gcs`, `/azure` and `/local`. Each cloud SDK is an optional peer that only its own subpath loads, so a server that uses S3 never installs the Google or Azure SDK.

## Install

- [npm package](https://www.npmjs.com/package/@storyshelf/storage) — install tarballs and version history.
- [Public API reference](/reference/storage/) — generated docs for every export; start here to learn the API.
- [Source on GitHub](https://github.com/GuptaSiddhant/storyshelf/tree/main/packages/storage) — package directory on `main`.

## When to use it

Choose a cloud backend for cloud or multi-node deployments. Each is a drop-in replacement for [local storage](../core/), and pairs naturally with the [Turso preset](../db/#presets-same-schema-different-driver) when the application is deployed without shared local disk. S3-compatible services (R2, MinIO, B2, Wasabi, Tigris) stay on `/s3`; GCS stays native because its S3 interoperability loses workload identity.
