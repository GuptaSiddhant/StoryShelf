# Public Website, Docs & Examples

## Website (Astro Starlight)

The public site lives in `apps/website/` and is built with **Astro Starlight** — MDX, no React, fast builds, built-in search (Pagefind), dark mode, and i18n. (StoryBooker used Docusaurus; Starlight was chosen for its lighter footprint.)

- **Homepage:** the "self-hosted Chromatic alternative" pitch.
- **Guides:** Getting started; CI (GitHub Actions, GitLab CI); Deployment (Docker/docker-compose, reverse proxy, subdomains + wildcard TLS); Auth (local, social, SSO/SAML, passkeys, none); Monorepo (one project per Storybook); Retention & labels; Migrating from Chromatic.
- **API reference:** generated from the Hono `OpenAPIHono` spec — the `openapi` script runs `packages/core/scripts/generate-openapi.ts` → `apps/website/public/openapi.json` (prebuild). The site serves the static spec at `/openapi.json` and a client-side Swagger UI at `/openapi/` (CDN, read-only, no try-it) loading that spec.
- The internal `docs/` (architecture + ADRs) remains engineering-facing; the site is curated user guides.

## Examples & Fixtures

`fixtures/` (outside workspaces, independent `pnpm` installs) holds Storybook fixtures for each supported major:

- **`fixtures/storybook-8`** — SB 8.6 Vite React (default, 7 stories)
- **`fixtures/storybook-9`** — SB 9 Vite React
- **`fixtures/storybook-10`** — SB 10 ESM + CSF-Next (filters `subtype:'test'`)
- **`fixtures/storybook-11`** — SB 11 alpha (upcoming)

Each has its own `package.json`/`pnpm-lock.yaml` and is built on demand (`pnpm install && pnpm run build-storybook`); `storybook-static/` is `.gitignored`. `apps/fly-app` deploys StoryShelf to fly.io as a public demo: a `fly.toml` + Dockerfile running the server, a persistent Fly volume for `--data-dir` (SQLite + screenshots), seeded with the `fixtures/storybook-8` project. Fly's `*.fly.dev` wildcard certs mean `publishedBaseDomain` subdomains work on the demo.

- CI workflow examples (`github-actions.yml`, `.gitlab-ci.yml`) are shown inline in the guides rather than shipped as runnable repos.

## Screenshots, API reference and checks

- Screenshots live in `apps/website/src/assets/screenshots/<name>-{light,dark}.png` and are rendered with the `<Screenshot name alt />` component (optimised by `astro:assets`, click-to-zoom). Refresh them with `nub run screenshots` (`screenshots:app` for the UI shots, `screenshots:og` for the social card).
- The REST API reference is generated by `starlight-openapi` from `public/openapi.json`, which `prebuild`/`predev` regenerate from the app's routes. Every route needs a `tags` entry and `summary`; `openapi.test.ts` enforces it.
- The TypeScript API reference (`/reference/<package>/`, nested under each package in the sidebar as "API") is generated at build time by `starlight-typedoc` from each package's `exports` map (`apps/website/typedoc-packages.mjs`; add a package by adding its slug to `SLUGS`; every package except `cli`, which has no source export, is generated). It pins `typescript@5.9` in the website only, because TypeDoc 0.28 cannot run on the workspace's TypeScript 7. The Drizzle re-export subpaths (`./orm*`) are skipped on purpose: documenting them takes ~90 s and 2 GB. `src/content/docs/reference/` is gitignored.
- Package pages and READMEs share content: `<Readme heading="Quick start" />` in `src/content/docs/packages/<slug>.mdx` is replaced by that `##` section of `packages/<slug>/README.md` (`plugins/remark-readme-section.mjs`; a missing heading fails the build). Put examples and anything npm/GitHub readers need in the README, and keep site-only content (the `PackageManagers` install block, cross-links) in the page. Inside shared sections write links to the site as absolute `https://storyshelf.js.org/...` URLs (rewritten to site paths here, so `check:links` covers them); other relative links resolve against the package on GitHub. READMEs are read at build time, so restart `nub run dev` after editing one.
- `src/content/docs/changelog.md` is generated (gitignored) from the root `CHANGELOG.md`.
- Quality gates (run in the CI `website` job): `nub run check:links` and `nub run check:a11y` (axe WCAG A/AA on sample pages in light, dark and mobile; needs a Chromium-based browser: Playwright's via `playwright-core install chromium`, or an installed Chrome with `A11Y_BROWSER_CHANNEL=chrome`, as CI does).
